Copilot Instruction Stack

Put stable knowledge where Copilot can reuse it. Put task-specific intent where it belongs. Keep the stack thin.

What goes where

  • Personal instructions - your standing style, language, and formatting preferences.
  • Repository instructions - repo-wide invariants, build/test commands, naming, architecture rules, and working assumptions.
  • Path-specific instructions - conventions that only apply in one area of the repo.
  • Prompt files - reusable prompts for specific tasks like explaining code, drafting tests, or writing PR summaries.
  • Inline prompts - one-off asks that should not become part of the project memory.

GitHub Docs notes that personal instructions apply across conversations, repository instructions add repository-specific guidance, and prompt files are reusable prompts for specific tasks.

Decision rule

  • Stable + personal - put it in personal instructions.
  • Stable + repo-wide - put it in repository instructions.
  • Stable + path-local - put it in path-specific instructions.
  • Repeatable task - make a prompt file.
  • One-off request - keep it in the prompt.

If you are unsure, do not promote the text into an instruction. Keep it ephemeral until it proves reusable.

The spec-driven loop

  1. Write a short user story that names the user, the need, and the outcome.
  2. Add acceptance criteria that are testable, observable, and brief.
  3. Capture only durable repo knowledge in instructions.
  4. Ask Copilot for a plan before code if the task is more than trivial.
  5. Execute one small change at a time, then verify it.
  6. Promote useful patterns into documentation or instructions only after you see them recur.

What to document

  • Build and test commands that Copilot should know
  • Directory layout and where important code lives
  • Domain terms and project-specific vocabulary
  • Non-obvious invariants and failure modes
  • Examples that teach a pattern Copilot should repeat

What not to document

  • Temporary task details
  • Long prose that merely repeats the README
  • Conflicting preferences for the same behavior
  • Per-task hacks that will expire next week
