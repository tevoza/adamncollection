TLS and Trust Basics

If you can keep three things separate, most network-security confusion disappears: the connection, the identity binding, and the trust decision.

What TLS does

TLS protects the connection. It gives you confidentiality, integrity, and usually server authentication. In plain English: eavesdroppers cannot read the traffic, attackers cannot silently change it, and the client can check who it is talking to.

  • ClientHello - the client says which versions, groups, and cipher suites it supports.
  • ServerHello - the server picks the parameters and starts key agreement.
  • Certificate - the server sends its identity chain.
  • Finished - both sides prove the handshake was not tampered with.
  • Application Data - the actual HTTP traffic begins, encrypted.

Primary source: RFC 8446.

What a certificate is

A certificate is a signed statement binding a subject identity to a public key. The private key stays secret with the owner. The CA signature is what lets strangers trust the binding.

That means the certificate is not the secret. The private key is.

Pieces to remember

  • Public key - safe to share
  • Private key - must stay secret
  • CA - signs the identity binding
  • Trust store - where trusted roots live

Primary source: RFC 5280.

The trust decision

When a client connects, it does not just ask, “is there a certificate?” It asks, “can I build a chain from this certificate back to a root I trust, and do the names, usage flags, and validity period all make sense?”

That is why installing a cert in the wrong store, missing an intermediate, or using the wrong hostname can break an otherwise valid-looking connection.

Why CSR matters

A CSR is how you ask a CA for a certificate without giving away your private key. It contains your public key, subject details, optional attributes, and a signature made with the private key to prove key ownership.

Primary source: RFC 2986.

Quick OpenSSL practice

# Inspect a live server certificate chain
openssl s_client -connect example.com:443 -servername example.com

# Create a private key and CSR
openssl req -new -newkey rsa:2048 -nodes -keyout key.pem -out request.csr

# Inspect the CSR
openssl req -in request.csr -noout -text

Check yourself

  • Why is a certificate not the same thing as a private key?
  • What does a CSR prove?
